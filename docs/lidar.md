# Обработка данных лидара

Узел `lidar_processor` (пакет `src/uav_lidar`) читает скан лидара, находит ближайшее препятствие и сообщает о нём
остальным узлам. Правила обработки лежат в `lidar_logic.py` (без ROS, проверяются тестами), сам узел — в `lidar_processor.py`.

## Схема

```
/lidar/scan (LaserScan, ~8 Гц) ──┐
/uav/raw_state (крен, тангаж) ───┴─> lidar_processor ──> /uav/lidar_status (LidarStatus, 5 Гц)
                                                              │
                                    telemetry_node ──────────┘ добавляет коды в alerts телеметрии
                                    diagnostics_node: понятные сообщения и уровни (WARN / ERROR)
```

Вход — `/lidar/scan` (`sensor_msgs/LaserScan`), а не `/lidar/points`: лидар двумерный, и скан содержит те же данные,
что облако точек, но без разбора упакованного массива. (В первой версии архитектуры был указан `/lidar/points`; решение 11
в [decisions.md](decisions.md).) Тема `/lidar/points` остаётся в записи группы моделирования, если понадобится 3D.

## Что считает узел

- **Корректный луч** — расстояние в диапазоне `range_min`…`range_max` (в симуляции 0,15…12 м). Значения `inf` («нет отражения»),
  `nan` и вне диапазона пропускаются.
- **Слепой сектор** — узкий сектор прямо по курсу (по умолчанию 6°), который закрывает мачта GPS. Лучи в нём не считаются.
  Ширина и центр задаются параметрами `blind_width_deg` и `blind_center_deg`; `0` отключает сектор. В симуляции мачту лидар не видит
  (она ближе минимальной дальности), на настоящем дроне данных в этом секторе не будет. Допустим ли такой сектор — вопрос к автопилоту (открыт).
- **Ближайшее препятствие** и его направление: 0° — по курсу, положительные углы — влево.
- **Четыре сектора** (спереди ±45°, слева, сзади, справа): ближайшее препятствие в каждом.
- **Наклон.** Если крен или тангаж больше `max_tilt_deg` (по умолчанию 15°), скан не используется (`scan_used = false`, расстояния `-1`):
  лидар наклоняется вместе с дроном, и лучи попадают в землю (на взлёте в записи число лучей с данными подскакивало до 200).
- **Потеря лидара.** Нет сканов дольше `scan_timeout_s` (1 с) — `scan_ok = false`, код `LIDAR_LOST`.

## Сообщение `uav_interfaces/msg/LidarStatus`

Тема `/uav/lidar_status`, 5 Гц. Расстояния в метрах, `-1.0` — «препятствий нет».

| Поле | Описание |
| --- | --- |
| `scan_ok` | лидар присылает данные |
| `scan_used` | скан использован (не пропущен из-за наклона) |
| `total_rays`, `valid_rays` | лучей всего / с корректным расстоянием |
| `nearest_m`, `nearest_angle_deg` | ближайшее препятствие и его направление |
| `front_m`, `left_m`, `back_m`, `right_m` | ближайшее по секторам |
| `level` | 0 норма, 1 предупреждение, 2 серьёзная проблема |
| `alerts` | коды: `OBSTACLE_NEAR`, `OBSTACLE_CLOSE`, `LIDAR_LOST` |

## Пороги и коды

| Код | Когда | Уровень | Параметр |
| --- | --- | --- | --- |
| `OBSTACLE_NEAR` | ближайшее препятствие ближе 3,0 м | предупреждение | `obstacle_warn_m` |
| `OBSTACLE_CLOSE` | ближе 1,0 м | серьёзная проблема | `obstacle_error_m` |
| `LIDAR_LOST` | нет сканов дольше 1 с | серьёзная проблема | `scan_timeout_s` |

Пороги 3 м и 1 м — наше предложение (дрон летит до 3 м/с, лидар видит до 12 м); их должен уточнить инженер по автопилоту.

Коды `telemetry_node` добавляет в поле `alerts` телеметрии (и значит, в журнал CSV). Статус старше 2 с игнорируется,
чтобы тревога не «залипла», если `lidar_processor` остановился. `diagnostics_node` выводит их понятным текстом и публикует в `/diagnostics`.

## Как запустить

Демо без симулятора (в контейнере, из корня репозитория):

```bash
colcon build --symlink-install
source install/setup.bash
ros2 launch uav_bringup lidar_demo.launch.py
```

`lidar_scan_player` публикует искусственный скан: стена спереди приближается с 8 м до 0,8 м и уходит, на 25-й секунде скан пропадает.
В терминале должны появиться по порядку: `OBSTACLE_NEAR` (около 12-й секунды), `OBSTACLE_CLOSE` (около 15-й), возврат к норме (около 17-й),
`LIDAR_LOST` (на 26-й секунде). Остановка — `Ctrl+C`; журнал `telemetry_logs/*.csv` содержит эти коды в колонке `alerts`.

С записью группы моделирования (rosbag2, MCAP; нужен установленный `ros-jazzy-rosbag2-storage-mcap`):

```bash
ros2 launch uav_bringup autopilot_px4.launch.py use_sim_time:=true lidar:=true consider_rc_loss:=false consider_gcs_loss:=false
ros2 bag play <папка_записи> --clock
```

Параметры узла: `obstacle_warn_m`, `obstacle_error_m`, `max_tilt_deg`, `scan_timeout_s`, `blind_width_deg`, `blind_center_deg`, `topic_scan`.
Пример: `ros2 run uav_lidar lidar_processor --ros-args -p obstacle_warn_m:=4.0`.

## Что не проверено

- На настоящей записи группы моделирования узел не запускался: файл записи в архив `simulation v0.6` не вошёл. Логика проверена
  тестами и искусственным сканом.
- Пороги, слепой сектор и ограничение по наклону — предложения, которые нужно подтвердить с группой автопилота.
